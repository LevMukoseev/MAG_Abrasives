## 6. Грабли / что не сработало

- **Vercel-бот `fix-react2shell-next`** создаёт PR с грозным названием про CVE, но содержимое может быть мусором: в нашем случае он не менял версии зависимостей вообще, зато удалил реальные фото и откатил код. **Всегда смотреть диф такого PR глазами, а не доверять названию.**
- **Браузерная песочница (`mcp__Claude_Browser__*`) работает при `document.hidden === true`** — панель превью не композитит кадры. Следствие: **`requestAnimationFrame` и `IntersectionObserver` в ней не срабатывают вообще** (проверено: коллбэк IO не пришёл и за 3 секунды). Значит scroll-reveal, счётчики и переключение прозрачности хедера в этом инструменте проверить невозможно — это ограничение инструмента, а не баг сайта. Проверять такое либо на живом деплое, либо через реальный Chrome (`mcp__claude-in-chrome__*`).
- **Скриншоты через Claude_Browser часто «плющат» вёрстку** в узкую колонку после скролла/ресайза — тоже баг инструмента. DOM-замеры (`getBoundingClientRect`, `naturalWidth`, `scrollWidth`) надёжны, скриншот — нет. Не чинить несуществующий баг сайта по одному плохому скриншоту.
- **Ленивые картинки в DOM выглядят «битыми»**: `img.complete === false` / `naturalWidth === 0` у изображений ниже вьюпорта — это нормальная ленивая загрузка, а не 404. Проверять по сетевым запросам, а не по DOM-флагам.
- **`{{c.icon}}` с HTML-строкой в Design Components (`.dc.html`)** — подстановка рендерит только текст, а не HTML; попытка вставить SVG сломала рендер. → Только текстовые значения (номерные бейджи); для настоящего HTML нужны `<dc-import>`-компоненты, не holes.
- **CSS Grid `repeat(N, 1fr)` без `minmax(0, 1fr)`** — на мобильной ширине трек не сжимается ниже min-content и вылезает за экран. Проверять `scrollWidth` vs `clientWidth` на 375px после любых grid-правок.
- **`npm run build` при работающем `npm run dev`** — оба пишут в `.next/`, прод-сборка портит кэш дев-сервера. → Всегда: остановить dev → `rm -rf .next` → поднять заново.

## 9. Как продолжить (инструкция для ассистента)

1. **Первым делом — спроси про выбор эскиза** (A/B/C или микс), дай ссылку из раздела 5. Не начинай кодить редизайн без этого решения, это не мелкая правка.
2. Когда направление выбрано — переноси его в `src/app/page.tsx` и связанные компоненты **как обычный Next.js/Tailwind код**, а не копируй HTML из design-canvas один в один (там инлайновые стили и структура под canvas-формат).
3. **Не трогай `main`** — ни мержем, ни PR, ни пушем — и не трогай Vercel/Cloudflare-конфиг проекта `mag-abrasives` без явного разрешения в чате каждый раз.
4. Работаем прямо в ветке `preprod`, пушим туда же — Vercel сам задеплоит staging.
5. Перед запуском dev-сервера после билда — `rm -rf .next`.
6. После правок прогоняй все три проверки: `npx tsc --noEmit`, `npm run lint`, `npm run build`.
7. Анимации/скролл-эффекты **не проверяются** во встроенном браузере (см. раздел 6, `document.hidden`) — проверяй на живом preprod-деплое.
8. Любые новые данные о компании бери из реальных источников (Яндекс.Диск, лифлеты, слова пользователя). Не выдумывай цифры, сертификаты, годы партнёрства и клиентские кейсы. Если данных не хватает — смотри раздел 7 и спрашивай.
