# HANDOFF.md — перенос контекста между сессиями

## 0. Быстрый старт (TL;DR)

Сайт-визитка + канал продаж GD-Abrasives (Next.js 15 / App Router / Tailwind), репо `MAG_Abrasives`, ветка `chore/redesign-cleanup-and-fixes`. Дебаг, чистка и контентная доработка одностраничника — **сделаны и задеплоены на preprod**. Сейчас в процессе — масштабный редизайн под сильно расширившуюся продуктовую линейку (13 категорий + 2 новых партнёра): 3 эскиза-концепта готовы (canvas + 3 отдельных HTML для партнёров), **ждём выбора направления от пользователя**, в реальный код сайта редизайн ещё не перенесён.

- Основной сайт компании GD-Abrasives (абразивный инструмент, станки, прокатные валки, лабораторное оборудование) — одновременно визитка и канал продаж.
- Изначально: ревью + техническая оптимизация + рефакторинг + редизайн под референс mag-test.tilda.ws.
- Позже пользователь расширил задачу: референс сам «на коленке», нужен полноценный масштабный редизайн, который реально продаёт, с учётом того что компания представляет **3 завода-партнёра** и **13 категорий продукции**, а не только шлифкруги.
- Критерий «готово» для текущего этапа: пользователь выбирает одно из 3 направлений редизайна (или просит смешать) → переносим выбранное в реальную Next.js-вёрстку → билд зелёный → задеплоено на preprod → пользователь проверяет и мержит в прод сам.

## 3. Ключевые решения и их причины

| Решение | Почему так | Что рассматривали и отклонили |
|---|---|---|
| Не мержить `chore/redesign-cleanup-and-fixes` в `main` без явного разрешения | Прямое указание пользователя в начале сессии | — |
| `preprod` — отдельная git-ветка + отдельный Vercel-проект `mag-abrasives-1` (Production Branch переключён на `preprod` вручную пользователем в UI) | Нужен стейджинг без риска для реального прод-домена | Менять Production Branch через API — недоступно ни в одном из Vercel MCP-тулов, только руками в дашборде |
| Никогда не трогать домен/DNS/deploy-конфиг проекта `mag-abrasives` (реальный прод) без предупреждения | Домен настроен под обход блокировок РКН, ошибка = сайт недоступен в РФ | — (см. память `vercel-cloudflare-rkn-caution`) |
| Убрал `backdrop-blur` с `fixed`-хедера вместо попытки «подпереть» его | Это конкретный известный баг Chromium (fixed+backdrop-filter+scroll → repaint ломается), не косметика | Пытался списать на глюк инструмента предпросмотра — но воспроизвёл на реальном задеплоенном билде, значит баг настоящий |
| Trust-блок собран только из **уже существующих на сайте** фактов (20 лет, офиц. представитель, диаметры кругов) | Прямая просьба не выдумывать цифры/сертификаты/лого клиентов, которые не проверить | Хотел изначально предложить сгенерированные стоковые фото — пользователь сам предложил реальные (Яндекс.Диск), это лучше |
| В картах партнёров указывал «Основана в 2017/2001» (факт основания завода), а не «партнёр с …» | Не было данных, с какого года именно ГД-Абрэзивс сотрудничает с этими заводами — не выдумывать | Изначально написал «Партнёр с 2005/2017» — сам поймал как фабрикацию при само-проверке, поправил |
| 3 эскиза редизайна — это **разные ставки** (широта / доверие / доказательство), не 3 оттенка одного | Так и просили — «эскизы», не финальный дизайн; директива design-skill не сходиться на одном вкусе без выбора пользователя | — |
| Иконки категорий в canvas заменены на номерные бейджи вместо SVG | `{{c.icon}}` с HTML-строкой ломает DC-шаблонизатор (рендерит как текст/крашится) — см. раздел 6 | Пытался передавать сырой SVG через hole — не работает в этом формате |

## 6. Грабли / что не сработало

- **`{{c.icon}}` с HTML-строкой в Design Components (`.dc.html`)** — хендлбарс-подстановка рендерит только текст, а не HTML; попытка вставить так динамический SVG сломала рендер (на страницу вылезал кусок внутреннего кода рантайма вместо иконки). → Чинится заменой на простые текстовые значения (номерные бейджи) через `renderVals()`; для настоящего HTML в DC-формате нужны отдельные `<dc-import>`-компоненты, не holes.
- **CSS Grid `repeat(N, 1fr)` без `minmax(0, 1fr)`** — на мобильной ширине контент трека может не сжиматься ниже min-content и вылезать за экран. Поймано на живом `.partners-grid` (3 колонки схлопывались в 2 на мобилке, текст вылезал). → Проверять `scrollWidth` vs `clientWidth` на 375px после любых grid-правок.
- **`npm run build` при работающем `npm run dev`** — оба процесса пишут в `.next/`, продакшен-сборка портит кэш дев-сервера (`Cannot find module './447.js'`). → Всегда: остановить dev-сервер → `rm -rf .next` → поднять заново.
- **Просмотр опубликованного claude.ai-артефакта через встроенный Browser-тул** — не авторизован в реальной сессии пользователя, отдаёт «Page not found». → Либо через `mcp__claude-in-chrome__*` (реальный Chrome юзера, уже залогинен), либо через WebFetch (для дизайн-канваса это ещё и единственный способ вытащить актуально сохранённое состояние).
- **Скриншоты через Claude_Browser часто «плющат» вёрстку в узкую колонку** после скролла/ресайза, особенно когда панель не видна пользователю — это баг самого инструмента предпросмотра, не сайта. Проверено многократно: DOM (`getBoundingClientRect`, `naturalWidth`, `scrollWidth`) даёт надёжный результат, скриншот — нет. Не паниковать и не чинить несуществующий баг сайта на основании одного плохого скриншота.
- **`python3`/`python` в git-bash на этой машине** резолвится в битую заглушку Windows Store. → Всегда вызывать по полному пути: `/c/Users/FPC_PC/AppData/Local/Programs/Python/Python312/python`.
- Юникод-имена файлов (кириллица), скачанные Python-скриптом через Windows-консоль, иногда портятся на уровне ФС (сам `os.listdir` возвращает мусор) — переименовывал по известному mapping сразу после скачивания, полагаясь на `path` из API, а не на отображаемое имя.

## 8. Как продолжить (инструкция для ассистента)

1. Начни с того, чтобы **дать пользователю посмотреть 3 эскиза ещё раз** (ссылка в разделе 5) и явно спросить, какое направление кодить — не начинай кодить редизайн без этого решения, это не мелкая правка.
2. Когда направление выбрано — переноси его в `src/app/page.tsx` и связанные компоненты **как обычный Next.js/Tailwind код**, а не копируй HTML из design-canvas один в один (там инлайновые стили и другая структура, специфичная под canvas-формат).
3. Не трогай `main` и Vercel/Cloudflare-конфиг реального прода (`mag-abrasives`) без явного предупреждения — см. раздел 3/4.
4. Перед запуском dev-сервера после билда — `rm -rf .next` (см. раздел 6).
5. Любые новые фото/данные о компании бери из реальных источников, которые даёт пользователь (Яндекс.Диск, лифлеты) — не генерируй цифры/сертификаты/клиентские кейсы от себя; если данных не хватает — спрашивай или явно помечай как черновик.
6. После правок — коммить в `chore/redesign-cleanup-and-fixes`, мержить fast-forward в `preprod`, пушить оба — как было заведено весь текущий сеанс.
